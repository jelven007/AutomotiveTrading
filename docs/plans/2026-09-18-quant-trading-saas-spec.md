## 1. 文档目的

本文档定义量化交易 SaaS 平台第一期的产品范围、业务规则、系统边界、
外部集成、安全要求、验收标准和交付阶段。

产品参考 SuperMind 的业务覆盖和工作流，但采用独立的信息架构、视觉设计、
领域模型和技术实现，不复制其源代码、品牌、数据或受保护的视觉资产。

本规格经确认后作为产品、设计、研发、测试、安全和运维团队的共同基线。
详细代码实施计划将在规格审批后另行生成。

## 3. 产品定位

平台面向个人量化投资者、专业交易者和中小型投研团队，提供覆盖三地股票
市场和币安数字资产市场的：

- 市场数据浏览与研究。
- 新闻、公告和研报聚合。
- Python 策略开发与版本管理。
- 大模型辅助的单股交易决策。
- 历史回测与绩效分析。
- 平台模拟交易与同花顺模拟盘。
- 富途、财信证券实盘交易。
- 币安生产现货、全仓杠杆、逐仓杠杆和 U 本位永续交易。
- 多租户管理、套餐计费、风险控制和审计。

平台的核心原则是：大模型负责生成候选决策，确定性规则负责控制执行。
任何模型输出都不能绕过组合协调、风险校验和账户授权直接提交订单。

## 4. 产品目标

1. 使用统一标的模型支持 A 股、港股、美股和币安数字资产。
2. 用户可以维护股票标的列表，并为策略定义可复用的参数模板。
3. 策略可获取券商或行情服务的实时数据，为每只股票独立调用指定模型。
4. 模型返回结构化的买入、卖出或观望建议，以及仓位、价格、有效期和理由。
5. 支持历史回测、平台模拟盘、同花顺模拟盘和受控实盘。
6. 支持人工确认与策略自动执行两种下单模式。
7. 实现租户隔离、角色权限、配额、计费、审计、监控、备份和灾备能力。
8. 数据源、模型厂商和券商接口可替换，不侵入策略领域核心逻辑。

## 5. 第一期非目标

- 不支持 A 股/港美期货、期权、债券和外汇。
- 币安一期不支持币本位合约、期权和其他未明确列入范围的衍生品。
- 不承诺微秒级或高频交易能力。
- 不提供交易所托管、柜台共址或跨券商智能路由。
- 不处理入金、出金、银证转账和资产托管。
- 不提供公开跟单、策略销售分成或收益承诺。
- 不在移动端提供完整 Python 策略编辑能力。
- 不允许未经确定性风控的大模型结果直接进入券商。
- 不在尚未取得正式协议和测试环境时宣称完成真实券商接入。

## 6. 用户、租户与权限

### 6.1 租户模型

租户代表一个个人工作空间或团队组织。所有租户业务数据必须包含
`tenant_id`，用户可以属于多个租户，但每个会话只有一个活动租户。

租户之间必须实现：

- 数据行级隔离。
- 缓存键隔离。
- 消息主题或消息头隔离。
- 对象存储路径隔离。
- 密钥与券商账户隔离。
- 计量和费用隔离。
- 日志查询权限隔离。

### 6.2 角色

| 角色 | 主要权限 |
| --- | --- |
| 平台管理员 | 租户、套餐、平台配置、全局风控和事件管理 |
| 租户管理员 | 成员、角色、配额、模型、券商连接和租户风控 |
| 研究员 | 数据、策略、参数、回测、模型评测 |
| 交易员 | 账户、人工委托、信号确认、急停和对账处理 |
| 审计员 | 只读查看策略版本、模型决策、订单、对账和审计日志 |

新增实盘账户、开启自动交易、修改高风险阈值和解除急停必须同时满足
角色权限与近期 MFA 验证。

## 7. 全局信息架构

桌面端使用固定顶部导航，包含五个一级菜单：

1. 首页
2. 资讯
3. 策略
4. 交易
5. 数据

全局区域提供：

- 证券搜索。
- A 股、港股、美股市场切换。
- 当前租户切换。
- 消息和风险告警。
- 服务状态。
- 帮助入口。
- 用户与安全设置。

移动端重点支持行情监控、告警处理、策略暂停、信号确认和紧急撤单。
策略编辑、批量交易、模型配置和风险策略配置仅在桌面端开放。

## 8. 首页规格

首页定位为操作型工作台，不采用营销落地页结构。

### 8.1 主要模块

- 三地市场指数与开闭市状态。
- 自选股实时行情。
- 模拟盘和实盘资产概览。
- 当日盈亏与累计收益。
- 正在运行、异常和暂停的策略。
- 回测任务状态。
- 待人工确认的策略信号。
- 风险告警、券商断连和数据延迟。
- 与自选标的相关的最新资讯。
- 创建策略、发起回测、人工下单和查看数据的快捷入口。

### 8.2 交互要求

- 用户可切换币种查看汇总资产。
- 所有跨币种汇总必须显示汇率时间。
- 模拟与实盘资产必须有持续可见的文字标识。
- 数据延迟不能只用颜色表达，必须显示时间和状态。
- 高风险告警必须支持确认、指派、跳转和审计。

### 9.1 内容类型

- 新闻。
- 上市公司公告。
- 研究报告。
- 宏观事件。
- 财报和业绩事件。
- 监管和交易所公告。

### 9.2 功能

- 按市场、行业、标的、来源、时间和内容类型筛选。

- 将资讯关联到标准证券代码和行业。

- 向策略引擎提供指定时点的资讯快照。

### 10.1 页面

- 我的策略。

### 10.2 策略生命周期

```text
draft
  -> validated
  -> backtested
  -> simulated
  -> approved
  -> active
  -> paused
  -> archived
```

自动实盘策略不得跳过校验、回测、模拟观察和审批状态。

草稿可持续修改；运行中的策略必须绑定不可变版本。修改策略或关键参数后，
必须发布新版本并重新执行必要的验证流程。

### 10.3 策略实体

策略至少包含：

- 名称、说明、负责人和标签。
- 支持市场。
- 股票标的池。
- Python 源码。
- 自定义参数 Schema 与参数值。
- 模型厂商、模型名称和模型参数。
- 提示词模板及版本。
- 输出 Schema 版本。
- 定时触发规则。
- 行情事件触发规则。
- 单股冷却时间。
- 每日调用次数与费用上限。
- 回测配置。
- 人工或自动执行模式。
- 模拟或实盘账户绑定。
- 风控策略。
- 生命周期状态。

## 11. 标的池

### 11.1 创建方式

- 手工添加证券。
- CSV 文件导入。
- 从自选股导入。
- 选择指数成分股。
- 按市场和行业筛选。
- 使用规则筛选并保存结果。

### 11.2 标准证券模型

```json
{
  "instrument_id": "uuid",
  "market": "CN|HK|US",
  "exchange": "SSE|SZSE|BSE|HKEX|NASDAQ|NYSE|AMEX",
  "symbol": "string",
  "name": "string",
  "currency": "CNY|HKD|USD",
  "timezone": "IANA timezone",
  "lot_size": 100,
  "status": "active|suspended|delisted"
}
```

数据供应商和券商的原始证券代码不得直接作为业务主键。系统维护显式映射表，
映射失败时禁止生成交易订单。

## 12. 自定义策略参数

参数使用 JSON Schema 描述，支持：

- 整数、小数、布尔值、文本、枚举、日期、时间和证券列表。
- 默认值、必填规则、取值范围、单位、显示名称和帮助说明。
- 回测、模拟和实盘环境覆盖值。
- 参数模板复制。
- 敏感参数独立加密存储。

策略发布时保存参数快照。历史决策、回测和订单必须能够定位到当时使用的
策略版本和参数版本。

## 13. AI 策略决策引擎

### 13.1 调用粒度

标的池内每只股票独立调用一次大模型。任务幂等键为：

```text
tenant_id
+ strategy_version_id
+ instrument_id
+ trigger_type
+ market_timestamp
```

同一幂等键只能生成一条有效决策。

### 13.2 触发方式

支持定时与事件双触发：

- 开盘前。
- 盘中固定间隔。
- 收盘前。
- 涨跌幅阈值。
- 成交量或换手率异动。
- 技术指标突破或交叉。
- 重要资讯或公告。
- 持仓和账户风险事件。

每个策略配置：

- 单股冷却时间。
- 每分钟和每日调用上限。
- 租户最大并发数。
- 每日模型费用预算。
- 重复事件合并窗口。
- 非交易时段策略。

### 13.3 输入快照

模型每次调用使用不可变的时点快照：

```json
{
  "strategy": {},
  "symbol": {},
  "market_snapshot": {},
  "technical_features": {},
  "fundamental_features": {},
  "news_context": [],
  "account_context": {},
  "position_context": {},
  "risk_context": {},
  "timestamps": {},
  "source_versions": {}
}
```

输入必须标注：

- 市场时间。
- 数据采集时间。
- 数据来源。
- 币种与时区。
- 新鲜度。
- 复权方式。
- 特征计算版本。

关键数据过期、缺失、标的停牌或市场休市时，不调用模型，并生成带原因的
`hold` 决策。

### 13.4 模型网关

统一支持 GPT、Claude Opus 和 DeepSeek，并提供：

- 租户级 API Key。
- 模型白名单和路由。
- 结构化输出。
- 超时、限流、熔断和重试。
- Token 与费用计量。
- 提示词版本管理。
- 输入脱敏和提示词注入防护。
- 模型调用日志与质量指标。
- 可选备用模型。

模型配置入口位于“租户设置 > 模型服务”，仅租户管理员可管理。普通成员只能
选择租户内已启用的模型。每个配置包含供应商类型、配置名称、`Base URL`、
`Model ID`、加密 API Key、超时、重试、并发、采样参数、Token 限额、
费用预算、允许使用的执行环境、默认/备用关系及健康状态。

供应商类型包括 OpenAI、Anthropic、DeepSeek、OpenAI Compatible、Ollama
和 vLLM。第一期实际调用前四类；Ollama/vLLM 支持保存和字段校验，但标记为
“待开放”，不能执行连接测试，也不能被策略选择。

API Key 写入后不可回显，只能替换或吊销。连接测试使用固定无敏感数据请求，
验证认证、模型存在性、结构化输出和延迟。删除被策略引用的模型配置前，
必须停用或迁移相关策略。

主模型失败后，备用模型的结果视为一条新决策，必须重新完成 Schema 校验、
组合协调和风控，不得继承主模型的执行资格。

### 13.5 模型输出契约

```json
{
  "action": "buy|sell|hold",
  "confidence": 0.0,
  "target_position_pct": 0.0,
  "order_type": "market|limit",
  "limit_price": null,
  "valid_until": "ISO-8601 timestamp",
  "reasons": ["string"],
  "risk_flags": ["string"],
  "data_timestamp": "ISO-8601 timestamp"
}
```

模型禁止输出或选择：

- 券商凭据。
- 交易账户密钥。
- 跳过风控标记。
- 风控阈值。
- 未授权券商账户。
- 任意可执行代码。

非法 JSON、Schema 不匹配、模型超时、低置信度、价格与动作矛盾或结果过期时，
统一降级为 `hold`。原始响应只用于审计和问题定位。

### 13.6 组合协调

单股决策完成后先进入组合协调器，处理：

- 多个买入决策争用现金。
- 总仓位和净敞口。
- 单股和行业集中度。
- 市场和币种暴露。
- 已存在的未成交订单。
- 可卖数量和结算约束。
- 策略优先级。
- 日内换手率和亏损限制。

协调器输出候选交易指令，不能直接调用券商。

## 14. Python 策略与回测

### 14.1 编辑器

- Python 语法高亮和静态检查。
- 策略模板与 API 自动补全。
- 参数面板。
- 运行日志。
- 数据预览。
- 版本差异。
- 保存草稿、校验、发布和回滚。

### 14.2 回测任务

回测采用异步任务。每个任务固定：

- 策略版本。
- 参数快照。
- 标的池快照。
- 数据快照版本。
- 时间范围。
- 基准。
- 手续费和滑点模型。
- 初始资金。
- 随机种子。

### 14.3 沙箱要求

Python Runner 运行在独立 Kubernetes Job 中：

- 非 root 用户。
- 只读根文件系统。
- 禁止特权模式。
- 限制 CPU、内存、磁盘、进程数和运行时间。
- 默认禁止外网访问。
- 只挂载当前任务输入和输出目录。
- 仅允许使用审批后的运行镜像和依赖。

### 14.4 回测结果

- 策略和基准净值曲线。
- 总收益和年化收益。
- 波动率、Sharpe、Sortino、Calmar。
- 最大回撤和回撤时长。
- 胜率、盈亏比、换手率、手续费和滑点。
- 持仓、委托和成交历史。
- 市场、行业和币种暴露。
- 模型决策及置信度分布。
- 完整复现元数据。

### 15.4 人工和自动执行

人工模式支持：

- 用户直接填写订单。
- 查看策略信号。
- 修改允许调整的价格和数量。
- 二次确认后提交。

自动模式按策略独立启用，默认关闭。启用条件：

1. 完成近期 MFA。

### 15.10 币安生产接入

一期支持以下产品：

- 生产现货。
- 全仓杠杆。
- 逐仓杠杆。
- U 本位永续合约。

一期不支持币本位合约和期权。币安 Connector 必须独立部署，只允许访问
币安官方域名，并将现货、全仓杠杆、逐仓杠杆和 U 本位永续作为不同
`account_scope` 处理。

账户绑定和凭据规则：

- 仅租户管理员可添加帐号，提交前要求近期 MFA。
- 优先使用 Ed25519 API Key，兼容 HMAC 和 RSA。
- API Key、私钥或 Secret 立即写入 KMS，数据库只保存 Secret 引用。
- 必须启用固定出口 IP 白名单。
- 禁止绑定具有提现权限的 Key。
- 查询权限和交易权限分开检查，默认先以只读状态连接。
- 启用生产写权限必须再次 MFA 并确认风险声明。
- Connector 必须同步币安服务器时间，签名请求的 `recvWindow` 默认不超过
  5 秒。

现货能力：

- 账户余额、开放委托、历史委托和成交查询。
- 市价单、限价单、撤单和订单状态补偿查询。
- 每笔请求使用平台幂等键生成稳定 `clientOrderId`。

杠杆能力：

- 全仓和逐仓账户、资产、负债、利息和风险率查询。
- 划转、借款、还款、下单、撤单和成交查询。
- 逐仓操作必须携带交易对，禁止跨交易对共享风险状态。
- 自动借还款必须显式配置，不得由界面默认开启。

U 本位永续能力：

- 账户余额、保证金、持仓、未实现盈亏和强平价查询。
- 单向/双向持仓模式、全仓/逐仓保证金模式和杠杆倍数同步。
- 市价/限价开平仓、撤单、`reduceOnly` 和成交查询。
- 风险降低操作与开仓请求分离，保护模式只允许撤单和减仓。

状态同步以 User Data Stream 为主、REST 补偿查询为辅。Listen Key 必须
续期并监控失效；断线后按事件时间和币安订单号补偿，禁止盲目重放订单。

## 16. 订单与成交

### 16.1 订单状态机

```text
created
  -> risk_checking
  -> ready
  -> submitting
  -> submitted
```

`submitted` 后允许：

```text
partially_filled -> filled
cancel_pending -> cancelled
rejected
unknown
```

`unknown` 状态禁止自动重试。Connector 必须使用券商订单号、客户端订单号、
账户、标的、方向、数量和时间窗口查询原委托，确认不存在后才能由人工决定。

### 16.2 下单幂等

- 所有写请求携带全局幂等键。
- 交易服务保存请求指纹。
- 相同幂等键和相同请求返回原结果。
- 相同幂等键和不同请求直接拒绝。
- 券商未提供幂等能力时，由 Connector 建立本地提交账本。

### 16.3 账本

平台使用复式或等价的不可变资金流水设计，记录：

- 现金冻结和释放。
- 买卖成交。
- 手续费与税费。
- 股息和公司行动。
- 汇兑。
- 人工调整及审批依据。

持仓与余额可由账本重建，禁止直接无痕修改。

## 17. 风险控制

### 17.1 下单前检查

- 用户、策略和账户权限。
- 市场交易时段。
- 标的状态和证券映射。
- 可用资金和可卖数量。
- 单笔最大金额和数量。
- 单股、行业和市场集中度。
- 总仓位、净敞口和币种敞口。
- 币安全仓/逐仓负债、利息、风险率和可借额度。
- U 本位合约杠杆、保证金模式、名义价值、维持保证金和强平距离。
- 合约开仓/减仓语义以及 `reduceOnly` 一致性。
- 资金费率、标记价格和指数价格新鲜度。
- 当前价偏离。
- 订单频率和重复订单。
- 当日换手率和亏损。
- 模型置信度。
- 决策有效期。
- 行情新鲜度。
- 租户、账户、策略、券商和平台急停。

### 17.2 运行中控制

- 实时计算账户风险。
- 达到阈值时暂停开仓。
- 支持只允许撤单和减仓的保护模式。
- 自动策略连续异常时自动暂停。
- 券商断连或数据过期时停止新增订单。
- 所有风控拒绝返回稳定错误码和可解释原因。

## 18. 对账

对账由券商回报事件和定时任务双重触发，比较：

- 平台委托与券商委托。
- 成交数量和价格。
- 持仓数量和可卖数量。
- 现金、冻结金额和购买力。
- 手续费与税费。

发现重大差异时：

1. 将账户切换为受限状态。
2. 禁止新增开仓订单。
3. 在安全前提下保留撤单与减仓能力。
4. 创建事件并通知授权人员。
5. 要求人工填写处理结论。
6. 完整记录解除限制的审批链路。

## 24. 安全要求

### 24.1 身份与授权

- 兼容 OIDC。
- 交易与管理操作启用 MFA。
- 短期 Access Token 和轮换 Refresh Token。
- 租户级 RBAC 与资源所有权双重检查。
- 会话撤销和登录设备记录。
- 服务身份采用最小权限。

### 24.2 密钥

- 券商和模型凭据存入火山引擎 KMS 或密钥管理服务。
- 浏览器和策略容器永不接触券商凭据。
- 日志脱敏账号、Token 和密钥。
- 支持密钥轮换和立即吊销。
- 审计密钥访问行为，但不记录密钥值。

### 24.3 Python 与提示词安全

- Python 代码在受限沙箱运行。
- 默认禁止外网。
- 校验上传文件与依赖白名单。
- 新闻、公告和供应商文本均视为不可信输入。
- 在提示词中隔离外部文本，禁止其携带工具指令。
- 模型响应必须通过严格 Schema 校验。
- 模型不能选择密钥、账户或跳过风控。

### 24.4 实盘安全

- 自动实盘默认关闭。
- 回测、模拟和实盘环境物理或逻辑强隔离。
- 自动交易启用需要二次确认。
- 支持多级急停。
- 交易审计只追加不覆盖。
- 每笔订单可追溯到用户操作或模型决策。

公开上线前必须完成法律与合规评审，包括数据授权、数据再分发、投资咨询边界、
适当性、风险披露、隐私保护和券商协议限制。

## 25. 故障处理

| 故障 | 默认行为 |
| --- | --- |
| 行情缺失或过期 | 观望，不生成开仓订单 |
| 模型超时或输出非法 | 观望，记录并按策略告警 |
| 下单后券商超时 | 标记 `unknown`，先查询后处理 |
| 券商断连 | 阻止新订单，保留安全恢复操作 |
| 币安用户数据流断开 | 暂停新增风险，REST 补偿并完成对账后恢复 |
| 杠杆预强平或强平 | 进入保护模式，只允许还款、追加保证金和减仓 |
| 合约 ADL 或强平风险过高 | 拒绝开仓和提高杠杆，只允许撤单与减仓 |
| Kafka 重复消息 | 幂等消费，不重复产生业务结果 |
| 风控服务不可用 | Fail closed，拒绝交易 |
| 审计服务不可用 | 持久缓冲；高风险写入无法保障时拒绝 |
| 对账差异 | 限制账户并创建事件 |

## 28. 火山引擎部署

推荐组件：

- VKE：业务服务、Connector 和隔离 Runner。
- 托管 MySQL 8：事务数据。
- 托管 Redis：缓存、锁和限流。
- Kafka 兼容消息服务：领域事件。
- TOS：策略、回测和不可变原始数据。
- KMS/密钥管理：券商和模型凭据。
- 镜像仓库：签名镜像。
- 负载均衡、WAF 和 DNS：入口流量。
- 日志、指标、追踪和告警服务。

开发、测试和生产使用不同项目、网络、数据库、Topic、Bucket 和密钥。
实盘 Connector 放置在独立命名空间和节点池，只开放明确的券商出口地址。
Binance Connector 使用固定出口 EIP，生产 Key 绑定 IP 白名单并禁用提现权限。

## 29. 测试策略

### 29.1 自动化测试

- 领域规则单元测试。
- 订单、资金和持仓不变量属性测试。
- 币安现货、全仓/逐仓杠杆和 U 本位永续产品隔离测试。
- 杠杆负债、借还款、风险率和合约强平保护测试。
- API Schema 与向后兼容测试。
- 数据、模型和券商 Adapter 契约测试。
- 事件 Schema、幂等和重放测试。
- MySQL、Redis、Kafka、TOS 集成测试。
- 策略触发到订单回报的端到端测试。
- 历史行情回放与结果复现测试。
- 租户隔离和权限测试。
- 提示词注入和恶意 Python 测试。
- 行情推送和事件突发负载测试。
- 供应商、模型、券商和基础设施故障注入。

### 29.2 强制不变量

- 租户不能读取或修改其他租户数据。
- 大模型输出不能直接提交订单。
- 一个订单幂等键不能产生两次券商委托。
- 正常执行不能产生负现金或负可卖持仓。
- 每笔实盘订单必须关联已审批决策或合法人工操作。
- 每次订单状态变更必须合法且可审计。
- 状态未知的订单不得自动重复提交。
- 币安现货、杠杆和合约资产不得跨帐号 Scope 混用。
- 保护模式不得执行借款、开仓或提高杠杆。
- `reduceOnly` 订单不得扩大或反向建立合约持仓。
- 已停用或过期的策略不得触发分析和交易。

## 31. 第一期验收标准

1. 用户可注册、创建或加入租户，并按角色访问资源。
2. 五个一级菜单可在桌面端完整使用，移动端可完成监控和确认操作。
3. 用户可浏览 A 股、港股、美股标准化 Mock 数据。
4. 用户可创建 Python 策略、配置股票列表和参数并发布不可变版本。
5. 租户管理员可配置、测试、启停和审计模型服务，普通成员不可访问密钥。
6. 用户可选择已启用的 GPT、Claude Opus、DeepSeek 或 OpenAI Compatible；
   Ollama/vLLM 第一期仅可配置，不可调用。
7. 策略支持定时与行情事件触发，并遵守冷却和预算。
8. 每只股票产生独立、结构化、可审计的模型决策。
9. 回测在隔离任务中执行并产生可复现报告。
10. 平台模拟盘支持委托、成交、持仓、资金、盈亏和风控。
11. 同花顺模拟盘在权限到位后通过真实环境验收；未到位时 Adapter
    必须通过已批准 Stub 的契约测试。
12. 富途、长桥与财信 Connector 在权限到位后通过测试环境、对账和故障测试。
13. 币安生产帐号通过权限最小化、固定出口 IP、现货、全仓/逐仓杠杆和
    U 本位永续的小额交易及对账验收。
14. 杠杆和合约进入预强平、强平或 ADL 风险状态时只能执行风险降低操作。
15. 人工与自动执行均可用，自动实盘未满足全部门槛时保持关闭。
16. 租户隔离、幂等、审计、备份、监控和回滚通过验收。

## 32. 外部依赖与待确认事项

以下事项不能仅由研发决定：

1. 富途账户所属司法辖区、可交易市场、行情套餐、部署地域及 SaaS 使用条款。
2. 同花顺模拟盘 API、服务端集成方式和授权合同。
3. 财信证券批准的量化通道、资产门槛、系统环境、IP 白名单和回报能力。
4. 长桥 OpenAPI 的 SaaS 调用、港美交易和行情授权。
5. 币安账户主体的司法辖区、产品资格、API 条款和固定出口 IP。
6. A 股、港股、美股生产行情和资讯的采购及再分发授权。
7. 支付渠道、发票和退款规则。
8. 产品是否构成投资咨询或自动化投资服务，以及对应牌照和披露要求。
9. 数据跨境、模型调用地域和个人信息处理要求。
