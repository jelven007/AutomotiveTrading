## 1. 测试目标

验证 mootdx 可获取数据被完整、可追踪地持久化，Tushare 校验不会覆盖原始
事实，前端能够正确展示行情、来源、质量和数据缺口。

| 测试层 | 范围 |

| 单元 | 代码映射、Decimal 转换、幂等键、质量规则、游标 |
| Provider 契约 | Quotes、Reader、Affair、Tushare 的标准模型 |
| 组件 | MySQL、ClickHouse、Redis、MinIO、Kafka 读写 |

## 3. 核心测试数据

- 沪市、深市、北交所证券各不少于 20 只。
- 包含正常交易、停牌、退市、ST、涨跌停、除权和新上市证券。
- 包含正常、重复、乱序、空响应、超时、字段缺失和异常单位。
- 包含跨午夜、集合竞价、午间休市、收盘及非交易日。
- 包含 F10 目录变更、正文变更和财务文件哈希变化。
- 包含无 `source_time`、源时间回退和本地时钟偏移。

## 5. 数据一致性测试

### 5.1 幂等键

- 快照：`provider + exchange + symbol + source_time + payload_hash`。
- K 线：`provider + exchange + symbol + interval + adjustment + event_time`。
- 分笔：优先使用源序号；无源序号时使用证券、交易日、时间、价格、数量、
  方向和原始偏移生成指纹。
- 文件：`provider + dataset + source_filename + content_hash`。

同一事件重复消费 10 次后，标准表只存在一个当前版本；原始层保留可审计的
接收批次关系。

### 5.2 数值和单位

- 价格、金额和数量不得经过浮点中间值。
- 成交量统一为股，保留原始单位和转换版本。
- 时区统一保存 UTC，接口同时返回市场时区。
- 复权价格不得覆盖不复权原始 K 线。

## 6. 性能测试

### 6.1 全市场快照

测试集按 5,500 只证券准备，持续运行一个完整交易时段。

| 指标 | 通过标准 |
| --- | --- |
| 自选股/策略池新鲜度 | P95 <= 3 s，P99 <= 5 s |
| 全市场单轮采集 | P95 <= 3 s，无法达到时必须标记降级 |
| 标准化与 ClickHouse 写入 | P95 <= 1 s |
| Redis 最新值更新 | P95 <= 200 ms |
| 丢失且未记录的证券 | 0 |
| 空响应识别率 | 100% |

### 6.2 查询与推送

| 场景 | 通过标准 |
| --- | --- |
| 最新行情单证券查询 | P95 <= 100 ms |
| 最新行情分页查询 | P95 <= 300 ms |
| 一年日 K 查询 | P95 <= 300 ms |
| 一个月分钟 K 查询 | P95 <= 500 ms |
| WebSocket 增量分发 | 服务内 P95 <= 200 ms |
| 前端 5,500 行数据集 | 页面只渲染视口窗口，无明显输入阻塞 |

压测报告必须记录主机 CPU、内存、磁盘类型、数据量、压缩率、网络环境、
mootdx 服务器和失败率。

## 7. 可靠性测试

| 编号 | 故障 | 预期 |
| --- | --- | --- |
| TC-CNMD-REL-001 | mootdx 服务器超时 | 熔断并切换服务器，批次状态可追踪 |
| TC-CNMD-REL-002 | 全部服务器不可用 | 数据状态变为 `unavailable`，不生成新信号 |
| TC-CNMD-REL-003 | Kafka 重复投递 | 标准表无重复当前记录 |
| TC-CNMD-REL-004 | 消费者写库后未提交 Offset | 重启后重复消费不产生重复 |
| TC-CNMD-REL-005 | ClickHouse 暂停 | 原始数据进入 WAL/MinIO，恢复后补写 |
| TC-CNMD-REL-006 | MinIO 暂停 | WAL 不丢失，批次不误报完成 |
| TC-CNMD-REL-007 | Redis 清空 | 可从 ClickHouse 重建最新行情 |
| TC-CNMD-REL-008 | 进程在分页中退出 | 从 MySQL 检查点继续 |
| TC-CNMD-REL-009 | Tushare 不可用 | 主采集继续，校验状态变为延迟 |
| TC-CNMD-REL-010 | 本地磁盘达到阈值 | 按 70/80/90% 策略告警和降级 |

## 9. 验收与退出标准

- 所有 P0/P1 用例通过。
- 全市场快照性能测试完成，真实结果写入容量报告。
- 任何不满足 3 秒目标的数据源状态都能正确降级。
- 原始层抽样记录与标准层可双向追踪。
- 随机抽取 100 只证券与 Tushare 日终数据核对，差异均有解释或质量事件。
- 连续运行五个交易日，无未记录数据缺口和不可恢复任务。
- 前端测试、TypeScript、ESLint、后端单元测试和契约测试全部通过。
