> 文档编号：QT-TP-BIN-NT-001
>
> 版本：1.0
>
> 日期：2026-09-20
>
> 状态：已确认，待执行

## 1. 目标

证明简化后的币安链路能够：

- 在登录后安全添加多个帐号，并保持单活动帐号。
- 使用 NautilusTrader 完成现货和 U 本位数据、执行和对账。
- 正确管理 U 本位杠杆、全仓/逐仓保证金和持仓模式。
- 在超时、断连、重启和帐号切换时不重复下单。
- 在不使用 KMS 的情况下避免凭据明文落盘或泄漏。

| 层级 | 环境 | 外部依赖 | 目标 |

## 3. 单元测试

### TC-BIN-NT-001 本地主密钥

- 创建权限为 `600` 的 32 字节主密钥文件。
- 验证服务正常加载。
- 分别使用缺失文件、目录、符号链接和 `640/644` 权限启动。
- 预期：异常配置 Fail Closed，不开放帐号和交易接口。

### TC-BIN-NT-002 凭据加密

- 使用同一帐号和相同凭据加密两次。
- 预期：nonce 和密文不同，均可解密。
- 修改密文、nonce、帐号 ID 和算法版本。
- 预期：认证失败，不返回部分明文。

### TC-BIN-NT-003 敏感信息清理

- 提交有效和无效凭据，覆盖成功、失败、取消和关闭弹窗。
- 预期：DOM、响应、异常、日志和 Trace 均无完整凭据。

### TC-BIN-NT-004 单活动帐号

- 创建三个 ready 帐号并依次激活。
- 预期：任意时刻只有一个 `active`；切换状态为串行。

### TC-BIN-NT-005 帐号切换失败

- 旧节点正常，新节点认证失败。
- 预期：写操作持续关闭，新帐号进入 error，不自动回切旧帐号。

### TC-BIN-NT-006 产品隔离

- Spot 断线、USD-M 正常；再反向执行。
- 预期：只冻结故障产品的写请求，状态分别展示。

### TC-BIN-NT-007 幂等

- 并发提交 20 个相同幂等键和相同请求。
- 预期：只创建一个平台订单和一次 Nautilus 提交。
- 相同幂等键配不同请求。
- 预期：返回 `idempotency.conflict`。

### TC-BIN-NT-008 本地风控

分别触发：

- 单笔最大名义金额。
- 单标的最大仓位。
- U 本位最大杠杆。
- 每日最大亏损。
- 急停和状态过期。

预期：在调用 Nautilus 前拒绝，错误码稳定。

## 4. Nautilus 组件测试

### TC-BIN-NT-020 客户端配置

- Spot 使用 `BinanceProductType.SPOT` 和 `BINANCE_SPOT`。
- U 本位使用 `BinanceProductType.USD_M` 和 `BINANCE_FUTURES`。
- Testnet 与生产环境 URL 不得混用。
- 两个客户端使用同一活动帐号凭据，但缓存和产品状态独立。

### TC-BIN-NT-021 Instrument 映射

- `BTCUSDT` 现货映射为 `BTCUSDT.BINANCE`。
- `BTCUSDT` 永续映射为 `BTCUSDT-PERP.BINANCE`。
- 数量、价格和最小名义金额遵循 instrument 元数据。

### TC-BIN-NT-022 订单映射

覆盖：

- Spot 市价、限价、IOC/FOK/GTC。
- USD-M 市价、限价、止损、止盈。
- 单向和双向持仓。
- `reduceOnly` 减仓不反向开仓。

### TC-BIN-NT-023 事件投影

- 订单状态按 Nautilus 事件更新。
- 重复成交 ID 只入库一次。
- 外部手工订单标记 `source=external`。
- 投影携带事件时间和新鲜度。

### TC-BIN-NT-024 对账

- 初次启动、正常重启、异常退出和流重连后执行对账。
- 未决订单通过 Client Order ID 或 Venue Order ID 恢复。
- 任一记录解析失败时不得发布“对账完成”。

## 5. API 与 Web 集成测试

### TC-BIN-NT-030 登录门禁

- 未登录访问币安页面和 API。
- 预期：页面跳转登录，API 返回 401。

### TC-BIN-NT-031 帐号添加

- 管理员完成 MFA 后添加 HMAC 和 Ed25519 帐号。
- 预期：保存脱敏摘要，产品能力测试可见，敏感字段清空。

### TC-BIN-NT-032 权限拒绝

- 普通用户添加、更新、删除或切换帐号。
- 预期：返回 403，数据库无变化。

### TC-BIN-NT-033 帐号切换

- 当前帐号有查询流但无未决写命令时切换。
- 预期：页面显示 switching，控件禁用；对账完成后新帐号标记为当前。

### TC-BIN-NT-034 工作区数据

- 分别选择现货和 U 本位标签。
- 预期：余额、订单、成交、持仓和状态来自对应产品，不显示旧帐号数据。

### TC-BIN-NT-035 U 本位设置

- 设置允许范围内杠杆及 `cross/isolated`。
- 预期：交易所确认后更新页面；失败时保留原值。

## 6. Testnet 契约测试

运行前必须显式设置：

```text
BINANCE_TESTNET_ENABLED=true
BINANCE_TESTNET_API_KEY=<secret>
BINANCE_TESTNET_SECRET=<secret>
```

未配置时测试必须 Skip，不得回退生产。

### TC-BIN-NT-040 Spot 生命周期

1. 连接 Spot Testnet。
2. 加载 BTCUSDT instrument。
3. 提交远离盘口的限价单。
4. 查询并撤单。
5. 验证订单事件和最终状态。

### TC-BIN-NT-041 USD-M 生命周期

1. 连接 USD-M Testnet。
2. 设置低杠杆和逐仓模式。
3. 提交最小允许订单。
4. 查询持仓，使用减仓语义平仓。
5. 验证余额、订单、成交和持仓归零。

### TC-BIN-NT-042 重启恢复

在订单存在时停止并重启 Trading Service。预期：

- 启动期间不接受新订单。
- 对账恢复订单和持仓。
- 不重复提交原订单。

### TC-BIN-NT-043 流中断

中断 WebSocket 但保留 REST。预期：

- 数据被标记为 stale。
- 新订单被暂停。
- 重连和对账后自动恢复。

## 7. 故障注入

| 故障 | 期望 |
| --- | --- |
| DNS 失败 | 状态 disconnected，无写请求 |
| TLS 握手失败 | 记录目标域名和阶段，不记录凭据 |
| REST 429/418 | 遵循 Nautilus 限频处理，禁止写请求盲目重试 |
| 下单响应丢失 | `pending_reconciliation`，等待外部事实 |
| MySQL 短时失败 | 不确认未持久化的本地命令 |
| 主密钥损坏 | 凭据不可解密，帐号进入 error |
| 旧节点停止超时 | 切换失败，不启动第二个节点 |
| 新节点对账失败 | 不开放交易 |
| 外部手工订单 | 纳入投影并标记 external |

## 10. 生产灰度

1. 只读连接并观察 24 小时。
2. 核对 Spot/USD-M 余额、开放订单和持仓。
3. 完成最小金额现货限价单和撤单。
4. 完成最小金额现货成交。
5. U 本位设置低杠杆和逐仓模式。
6. 完成最小仓位开仓和 `reduceOnly` 平仓。
7. 重启服务并确认账实一致。
8. 演练急停。

任一步出现重复订单、未决订单无法收敛、凭据泄漏或账实不符，立即停止灰度。
