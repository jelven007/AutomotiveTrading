## 缺陷分析与修复证据

编码前回归运行 10 个用例：原有 5 个通过，新增 5 个失败，确认以下问题：

1. 毫秒源时间被秒级格式拒绝。
2. 缺失源时间冒用采集时间并被标记 healthy。
3. 延迟重放按旧采集时间评估新鲜度。
4. 单条坏记录阻断整批原始数据保存。
5. 成功批次重试产生重复写入。

以上用例保留，业务实现修复后通过。第二轮发现连接初始化误用了 logging API，
测试先确认失败后修复。真实 Linux 启动还发现失败连接清理会抛 `Errno 107`，
已将清理异常隔离，保持有界节点探测继续执行。

第三轮专项范围为 Provider 和其快照解析调用。新增 5 个二进制响应解析场景，
包含正常毫秒、零时间、两个短整数及越界时间。修复前 10 个 Provider 用例中
7 个通过、3 个失败，确认异常时间不能阻断同批记录。隔离解析适配完成后全部通过。
实际返回值 `9270001` 另经直接验证转换为 `09:27:00.006`；
`100` 保留原始值、派生时间为未知。未修改第三方依赖文件或全局类。

本次测试流程按准备、上下文、范围、缺陷分析、生成验证修复、覆盖率、报告顺序执行，
三轮均执行 `utree flush`。未指定覆盖率门槛，按技能规则跳过覆盖率统计；
以上通过数量不等于覆盖率。

## 验收边界

- 证券范围固定为 MOOTDX/TDX 前缀筛选的沪深候选 A 股集合，
  不提供交易所权威全集保证。
- 北交所属于范围外，不计入应采、覆盖分母、缺口及验收待办。
- 周末快照日期根据最新日 K 推定，保留 `daily_bar_inferred` 标记，不能作为 healthy。
- 2 秒是调度目标，不是已达成的采集延迟。交易时段 P95 ≤3 秒与五日稳定性尚待验收。
- 以上 duration 仅含快照轮询及本地保存，不含首次证券同步和异步 HTTP 入库；
  交易时段还需验证端到端延迟、发送吞吐和队列积压。
- MySQL 和 ClickHouse 无分布式事务。失败重放可造成原始物理重复，
  按确定性的 event_id 核验逻辑唯一行。
