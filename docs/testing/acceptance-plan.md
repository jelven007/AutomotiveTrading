# 用户验收与发布准入方案

> 文档编号：QT-UAT-001
>
> 版本：1.2-draft

币安验收细节以
[`QT-TP-BIN-NT-001`](binance-nautilustrader-test-plan.md)
为准。

## 1. 验收角色

- 产品负责人：确认业务范围。
- 租户管理员代表：确认配置与管理。
- 研究员代表：确认数据、策略、模型和回测。
- 交易员代表：确认模拟与实盘流程。
- 安全负责人：确认身份、密钥、沙箱和审计。
- 运维负责人：确认监控、备份、灾备和回滚。
- 法务/合规：确认数据与交易开放边界。

## 2. 业务验收场景

1. 创建租户、邀请成员并分配角色。
2. 管理员配置 GPT/Claude/DeepSeek/OpenAI Compatible。
3. 保存 Ollama/vLLM 配置并确认一期不可调用。
4. 创建包含三市场股票的标的池。
5. 创建 Python 策略和参数模板。
6. 配置定时与行情事件触发。
7. 每只股票独立生成买入、卖出或观望决策。
8. 执行回测并查看完整报告。
9. 将策略部署到平台模拟盘。
10. 在同花顺测试环境运行模拟盘策略。
11. 在富途、长桥和财信测试环境完成人工下单、撤单与对账。
12. 登录后从“交易 → 币安”添加单一 HMAC 生产帐号，验证本地加密、权限检查和
    固定出口 IP。
13. 核对币安现货余额、U 本位余额和非零持仓，并验证单侧故障局部降级。
14. 使用有效和无效新凭据重新绑定，确认成功覆盖且失败时保留旧帐号。
15. Testnet 完成现货和 U 本位市价/限价单及单笔撤单。
16. Testnet 完成 U 本位杠杆和 `cross|isolated` 保证金模式。
17. 完成幂等、超时、断线和重启核对后，进行最小资金生产灰度。
18. 自动实盘另行设计和审批，不属于本轮发布。

## 3. 发布关卡

| 关卡 | 通过条件 |
| --- | --- |
| G0 规格 | SRS、技术、测试和安全文档审批 |
| G1 内部 | P0/P1 自动化通过，无高危缺陷 |
| G2 模拟 | 连续观察期无重复订单和账实差异 |
| G3 证券通道 | 同花顺、财信、富途、长桥联调与故障演练通过 |
| G4 币安只读 | 单帐号、Nautilus Spot/USD-M、权限、余额和持仓查询通过 |
| G5 小额灰度 | 白名单账户、人工值守、现货和 U 本位分别限额 |
| G6 正式 | 法务、安全、运维和业务共同签署 |

## 4. 自动实盘准入

每个策略单独验证：

- 已发布且不可变。
- 回测满足租户设置的最低样本期。
- 模拟运行达到观察天数。
- 无未解决高风险告警。
- 绑定有效账户和风控策略。
- 模型配置健康且允许实盘。
- 用户完成 MFA 和风险确认。
- 设置单日损失、单笔金额和急停。
- 币安按现货和 U 本位分别审批。
- 合约已设置最大杠杆、最大名义价值、保证金模式和强平距离阈值。

## 5. 灰度约束

- 初期仅白名单租户。
- 限定标的、金额、交易时段和每日订单数。
- 币安生产灰度从只读开始，再依次开放现货和 U 本位永续。
- 首次 U 本位交易仅允许人工提交，不得直接开启策略自动执行。
- Nautilus 客户端异常立即冻结对应产品写入。
- 每日核对平台订单、成交和交易所状态。
- 灰度期间不得自动放宽风控阈值。

## 6. 验收记录

记录版本、环境、测试数据、外部账号类型、执行人、证据、缺陷和签字。
未取得真实外部权限的集成只能标记为 `Blocked` 或 `Stub Verified`，
不得标记为生产验收通过。
