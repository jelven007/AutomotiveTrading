# 币安 NautilusTrader 接入需求

> 文档编号：QT-REQ-BIN-NT-001
>
> 版本：1.0
>
> 日期：2026-09-20

> 状态：已确认，待实施

## 1. 背景

现有币安方案同时引入自研 REST 签名、四类帐号 Scope、独立 Connector、
KMS Adapter、Risk Service、Outbox 和后续 Reconciliation Service，超过个人
单机部署的当前需要。本需求以 NautilusTrader 替换自研币安协议栈，并将运行边界
收敛到单个 Trading Service。

本文取代以下文档中的币安范围和实现约束：

- `2026-09-19-trading-account-and-binance-integration-design.md`
- `2026-09-19-binance-production-trading-implementation-plan.md`
- `2026-09-19-binance-read-only-wiring-design.md`
- `2026-09-19-binance-read-only-wiring-implementation-plan.md`

旧文档仅保留为历史记录。

## 2. 目标

1. 用户登录后可在“交易 → 币安”页面添加和管理真实币安帐号。
2. 支持保存多个帐号，但同一时间只能启用一个帐号。
3. 支持币安现货和 U 本位合约。
4. 支持 U 本位杠杆倍数、全仓/逐仓保证金模式和单向/双向持仓模式。
5. 由 NautilusTrader 负责行情、执行、私有数据流和执行状态对账。
6. 使用本地主密钥加密凭据，不依赖云 KMS 或币安官方 SDK。
7. 保留最小但有效的风控、幂等、急停、审计和生产灰度能力。

## 3. 非目标

- 不支持现货全仓杠杆、现货逐仓杠杆、借款、还款和资产划转。
- 不支持币本位合约、期权和交割合约的业务入口。
- 不支持多个币安帐号同时在线交易。
- 不支持按租户独立部署 Nautilus 节点。
- 不在浏览器、日志、Trace 或普通配置中保存明文凭据。
- 不继续维护自研币安签名、REST/WebSocket 客户端或 User Data Stream。
- 本轮不开放无人值守自动实盘。

## 4. 用户流程

### 4.1 添加帐号

1. 用户完成系统登录。
2. 进入“交易 → 币安”。
3. 点击“添加帐号”。
4. 输入帐号别名、API Key、HMAC Secret 或 Ed25519 私钥。
5. 确认 API Key 已绑定固定出口 IP 且未开启提现权限。
6. 后端加密凭据并保存帐号元数据。
7. 系统执行只读连接和产品可用性测试。
8. 页面显示脱敏 Key 指纹、现货/U 本位状态和最近测试时间。

### 4.2 启用帐号

1. 用户选择一个已保存帐号并点击“设为当前帐号”。
2. 系统暂停接受新订单。
3. 当前 Nautilus 节点完成在途命令处理后停止。
4. 系统解密目标帐号凭据并创建新的 Spot、USD-M 客户端。
5. 完成余额、订单、成交和持仓对账。
6. 对账成功后将帐号标记为 `active` 并开放人工交易。

切换失败时，新帐号保持不可交易，不自动回切旧帐号。

## 5. 功能需求

### 5.1 身份与帐号

- **FR-BIN-NT-001** 币安页面和所有接口必须要求已登录会话。
- **FR-BIN-NT-002** 只有管理员角色可以添加、更新、删除和启用帐号。
- **FR-BIN-NT-003** 系统可以保存多个币安帐号，但只允许一个活动帐号。
- **FR-BIN-NT-004** 帐号响应不得包含 API Key、Secret、私钥、密文或 nonce。
- **FR-BIN-NT-005** 删除活动帐号前必须先停用，且不存在未决订单。

### 5.2 凭据

- **FR-BIN-NT-006** 支持 HMAC 和 Ed25519；不支持 RSA。
- **FR-BIN-NT-007** 凭据使用 AES-256-GCM 加密后保存到 MySQL。
- **FR-BIN-NT-008** 主密钥来自只读挂载文件，宿主机权限必须为 `600`。
- **FR-BIN-NT-009** 浏览器提交、成功、失败或取消后必须清除敏感字段。
- **FR-BIN-NT-010** 添加帐号前必须人工确认固定出口 IP 和禁止提现。

### 5.3 现货

- **FR-BIN-NT-011** 支持余额、开放订单、历史订单和成交查询。
- **FR-BIN-NT-012** 支持市价单、限价单、撤单和全部撤单。
- **FR-BIN-NT-013** 使用 Nautilus instrument 元数据校验数量、价格和最小名义金额。

### 5.4 U 本位

- **FR-BIN-NT-014** 支持余额、持仓、开放订单、历史订单和成交查询。
- **FR-BIN-NT-015** 支持市价、限价、止损和止盈订单。
- **FR-BIN-NT-016** 支持设置合约杠杆倍数。
- **FR-BIN-NT-017** 支持按交易对设置 `cross` 或 `isolated` 保证金模式。
- **FR-BIN-NT-018** 支持单向和双向持仓模式，并正确处理 `reduceOnly`。
- **FR-BIN-NT-019** 禁止超过本地最大杠杆和最大名义价值限制。

### 5.5 执行安全

- **FR-BIN-NT-020** 所有下单和撤单请求必须携带 `Idempotency-Key`。
- **FR-BIN-NT-021** 写请求结果不确定时不得自动重复提交。
- **FR-BIN-NT-022** 私有数据流断开或状态过期时必须暂停对应产品的新订单。
- **FR-BIN-NT-023** 服务启动和帐号切换后必须先完成对账再开放交易。
- **FR-BIN-NT-024** 急停状态必须持久化，重启后继续生效。
- **FR-BIN-NT-025** 自动策略交易默认关闭，首轮只允许人工交易。

## 6. 非功能需求

- **NFR-BIN-NT-001** Trading Service 必须使用 Python 3.12。
- **NFR-BIN-NT-002** NautilusTrader 必须精确锁定版本，升级必须通过兼容测试。
- **NFR-BIN-NT-003** 连接状态变化应在 5 秒内反映到 Web。
- **NFR-BIN-NT-004** 已确认订单和成交不得因服务重启而丢失。
- **NFR-BIN-NT-005** API、日志和错误响应不得泄漏任何凭据材料。
- **NFR-BIN-NT-006** Spot 与 USD-M 故障必须隔离；单侧故障不得阻断另一侧只读查询。
- **NFR-BIN-NT-007** 系统必须提供可脱敏导出的诊断信息。

## 7. 外部准入

生产接入前必须满足：

- ECS 到币安官方 Spot、USD-M REST 和 WebSocket 网络可用。
- ECS 使用固定公网出口，API Key 已配置 IP 白名单。
- API Key 未开启提现及通用划转权限。
- 帐号已开通 U 本位合约并完成交易所要求的资格确认。
- 公网管理入口使用可信 HTTPS 证书。
- 用户已确认所在司法辖区、币安服务条款和当地法律允许相关交易。

## 8. 验收标准

1. 登录后可添加两个帐号，并且数据库中不存在明文凭据。
2. 任意时刻只有一个帐号为 `active`。
3. 帐号切换过程中无法提交订单，完成对账后恢复。
4. Testnet 完成现货和 U 本位下单、撤单、成交及重启恢复。
5. U 本位杠杆与保证金模式设置结果和币安一致。
6. 网络超时不会造成重复订单。
7. 生产按只读、最小现货、低杠杆逐仓合约顺序完成灰度。
