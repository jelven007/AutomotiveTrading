# 币安 NautilusTrader 接入需求

> 文档编号：QT-REQ-BIN-NT-001
>
> 版本：2.0
>
> 日期：2026-09-21
>
> 状态：已确认，待实施

## 1. 背景

系统部署在个人 ECS 上，当前目标是先完成一个真实币安账号的安全接入和账户信息
查询，再在同一架构上增加人工交易。此前的多账号切换、全量订单类型、独立风控和
后台同步设计超过当前需要。

本需求以
[`QT-DES-BIN-SIMPLE-001`](../plans/2026-09-21-binance-single-account-phased-design.md)
为设计基线，取代 1.0 版本中的多账号和一次性交付完整交易范围。

## 2. 目标

1. 用户登录后可绑定一个真实币安生产账号。
2. 重新绑定时安全覆盖旧账号，失败时不影响旧账号。
3. 阶段一查询账号权限、现货余额、U 本位余额和 U 本位持仓。
4. 阶段二支持人工现货和 U 本位下单、撤单、杠杆及保证金模式。
5. 由 NautilusTrader 提供统一的账户状态和执行运行时。
6. 使用本地主密钥加密凭据，不依赖云 KMS。

## 3. 分阶段范围

### 3.1 阶段一：只读

- 单账号首次绑定、重新绑定和删除。
- HMAC API Key 和 Secret。
- API Key 权限查询。
- 现货非零余额查询。
- U 本位余额和非零持仓查询。
- 页面手动刷新和最多 5 秒的进程内快照。
- Spot 与 USD-M 单侧失败时局部降级。

### 3.2 阶段二：人工交易

- 现货市价单、限价单和单笔撤单。
- U 本位市价单、限价单和单笔撤单。
- 按交易对设置 U 本位杠杆。
- 按交易对设置 `cross` 或 `isolated` 保证金模式。
- 平台订单、成交和幂等记录持久化。
- MFA 短时交易会话。

## 4. 非目标

- 多币安账号、账号激活、停用或切换。
- Ed25519 和 RSA 凭据。
- 余额、持仓和权限历史持久化。
- 后台定时同步和页面 WebSocket 推送。
- 批量撤单、止盈止损、条件单和双向持仓。
- 现货杠杆、借款、还款和资产划转。
- 币本位合约、交割合约和期权。
- 自动策略下单。
- 浏览器直接调用币安 API。

## 5. 用户流程

### 5.1 首次绑定

1. 用户登录并进入“交易 → 币安”。
2. 点击“添加账号”。
3. 输入别名、API Key 和 API Secret。
4. 确认 API Key 已绑定 ECS 固定出口 IP。
5. 系统检查读取权限，并拒绝开启提现或划转权限的 Key。
6. 系统启动候选 Nautilus Runtime，读取三类目标数据。
7. 验证成功后加密并保存凭据，页面展示账户数据。

### 5.2 重新绑定

1. 用户点击“重新绑定”并输入新凭据。
2. 系统在不停止旧运行时的情况下验证新凭据。
3. 验证成功后原子覆盖旧账号和密文，并切换运行时。
4. 验证失败时保留旧账号和旧运行时。

### 5.3 信息查询

1. 页面打开时请求聚合账户信息。
2. 系统分别读取权限、Spot 和 USD-M 数据。
3. 任一数据源失败时只标记对应区域，不隐藏其他可用数据。
4. 用户点击刷新时绕过 5 秒内存快照。

### 5.4 人工交易

1. 用户完成 MFA，建立最长 15 分钟的交易会话。
2. 页面校验运行时、权限和数据新鲜度。
3. 用户提交订单、撤单、杠杆或保证金模式请求。
4. 系统持久化幂等记录后调用 Nautilus。
5. 结果不确定时进入待核对状态，不自动重发。

## 6. 功能需求

### 6.1 身份与单账号

- **FR-BIN-NT-001** 币安页面和全部接口必须要求已登录会话。
- **FR-BIN-NT-002** 每个用户最多保存一个币安账号。
- **FR-BIN-NT-003** 重新绑定必须覆盖旧账号，不创建第二条账号记录。
- **FR-BIN-NT-004** 新凭据验证失败时必须保留旧账号、旧密文和旧运行时。
- **FR-BIN-NT-005** 账号响应不得包含 API Key、Secret、密文或 nonce。

### 6.2 凭据

- **FR-BIN-NT-006** 首版只支持 HMAC API Key 和 Secret。
- **FR-BIN-NT-007** 凭据必须使用 AES-256-GCM 加密后保存到 MySQL。
- **FR-BIN-NT-008** 主密钥必须来自只读挂载文件，宿主机权限为 `600`。
- **FR-BIN-NT-009** 浏览器在提交、失败、成功或取消后必须清除敏感字段。
- **FR-BIN-NT-010** 绑定前必须确认固定出口 IP 白名单。
- **FR-BIN-NT-011** 系统必须拒绝无读取权限或开启提现、内部划转、通用划转的 Key。

### 6.3 阶段一查询

- **FR-BIN-NT-012** 系统必须返回 API Key 的读取、现货交易、U 本位交易、提现和
  划转权限状态。
- **FR-BIN-NT-013** 系统必须查询并返回现货非零余额。
- **FR-BIN-NT-014** 系统必须查询并返回 U 本位余额。
- **FR-BIN-NT-015** 系统必须查询并返回 U 本位非零持仓。
- **FR-BIN-NT-016** 聚合查询必须包含各区域状态和统一 `as_of` 时间。
- **FR-BIN-NT-017** Spot 或 USD-M 单侧失败不得阻断另一侧结果。
- **FR-BIN-NT-018** 手动刷新必须绕过最多 5 秒的进程内快照。
- **FR-BIN-NT-019** 权限、余额和持仓不得作为历史业务数据持久化。

### 6.4 阶段二交易

- **FR-BIN-NT-020** 交易写操作必须要求有效的短时 MFA 交易会话。
- **FR-BIN-NT-021** 现货和 U 本位必须支持市价单和限价单。
- **FR-BIN-NT-022** 系统必须支持单笔订单撤销。
- **FR-BIN-NT-023** 系统必须支持按交易对设置 U 本位杠杆。
- **FR-BIN-NT-024** 系统必须支持按交易对设置 `cross|isolated` 保证金模式。
- **FR-BIN-NT-025** 所有交易写请求必须携带 `Idempotency-Key`。
- **FR-BIN-NT-026** 同一幂等键和相同请求只能调用 Nautilus 一次。
- **FR-BIN-NT-027** 写请求结果不确定时必须进入 `pending_reconciliation`，不得
  自动重发。
- **FR-BIN-NT-028** Nautilus 未就绪、状态过期或启动对账未完成时必须拒绝写操作。
- **FR-BIN-NT-029** 自动策略来源的订单必须被拒绝。
- **FR-BIN-NT-030** 数量、价格和最小名义金额必须使用 Nautilus instrument
  元数据校验。

## 7. 非功能需求

- **NFR-BIN-NT-001** Trading Service 使用 Python 3.12。
- **NFR-BIN-NT-002** NautilusTrader 精确锁定为 `1.231.0`，升级必须单独回归。
- **NFR-BIN-NT-003** 普通聚合查询在网络正常时 P95 不超过 3 秒。
- **NFR-BIN-NT-004** 进程内快照最大有效期为 5 秒。
- **NFR-BIN-NT-005** API、日志、Trace 和浏览器不得泄漏任何凭据材料。
- **NFR-BIN-NT-006** Spot 与 USD-M 故障必须隔离。
- **NFR-BIN-NT-007** 阶段二已确认订单和成交不得因服务重启而丢失。
- **NFR-BIN-NT-008** 所有错误必须返回稳定错误码和可脱敏的诊断信息。

## 8. 外部准入

阶段一上线前：

- ECS 到 Binance Spot、USD-M REST 和 WebSocket 可用。
- ECS 使用固定公网出口，API Key 配置该 IP 白名单。
- API Key 开启读取权限，关闭提现和全部划转权限。
- U 本位账户已经开通。
- 公网管理入口使用可信 HTTPS。

阶段二启用前还必须满足：

- API Key 按需开启现货和 U 本位交易权限。
- Binance Testnet 完成订单和设置类验收。
- `LIVE_TRADING_ENABLED=true` 由人工显式配置。
- MFA 交易会话和幂等存储已经启用。

## 9. 验收标准

### 9.1 阶段一

1. 首次绑定后能够查询权限、现货余额、U 本位余额和非零持仓。
2. 数据库中每个用户最多一条币安账号记录。
3. 重新绑定成功后旧密文被删除，新运行时生效。
4. 重新绑定失败时旧账号仍可查询。
5. Spot 或 USD-M 单侧故障时页面局部降级。
6. 数据库、响应、日志和浏览器中无明文凭据。

### 9.2 阶段二

1. Testnet 完成现货和 U 本位市价、限价下单及单笔撤单。
2. 相同幂等请求只产生一次 Nautilus 提交。
3. U 本位杠杆和保证金模式与交易所结果一致。
4. 超时结果不自动重发，并可在恢复后核对。
5. 无 MFA 会话、运行时未就绪或自动策略来源时拒绝写操作。
