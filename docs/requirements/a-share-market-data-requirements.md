# A 股行情与分析系统需求规格

> 文档编号：QT-SRS-CNMD-001
>
> 状态：Review
>
> 版本：0.3
>
> 日期：2026-09-20

## 1. 目的

本文定义个人内部使用的 A 股行情采集、持久化、查询与前端分析需求。
本文是 `FR-DATA-*` 的专项细化，实施前必须与技术设计和测试计划同步评审。

本文中的 `mddtdx` 按上下文统一解释为 `mootdx`。

2026-09-20 范围变更：用户确认仅需要上海证券交易所（SSE）和深圳证券交易所
（SZSE）的 A 股数据。本文及相关文档中的“全市场”“全量证券”均指沪深 A 股。
该范围约束适用于主数据、实时及历史行情、财务资料、查询展示、覆盖统计和验收。

## 2. 范围与边界

### 2.1 已确认范围

- 覆盖上海证券交易所和深圳证券交易所的全部 A 股证券。
- 自选股和策略池行情新鲜度目标为 P95 不超过 3 秒。
- 持久化保存 mootdx 能够获取的所有数据类型。
- MOOTDX 是唯一 A 股数据源，证券范围按 TDX 沪深列表和代码前缀筛选。
- 提供可操作的前端行情分析和数据运维页面。
- 系统仅供个人内部使用，不向第三方再分发行情。

### 2.2 mootdx 数据范围

| 通道 | 数据 |
| --- | --- |
| `Quotes` | 实时行情、五档盘口、证券列表、指数 K 线、证券 K 线、分时、历史分时、当前分笔、历史分笔、板块、F10、除权除息、财务摘要 |
| `Reader` | 通达信本地日线、1 分钟线、5 分钟线、标准及自定义板块文件 |
| `Affair` | 专业财务文件目录、原始 ZIP/DAT 文件及解析后的财务指标 |

### 2.3 明确限制

- 北交所数据不在需求范围内，不安排其数据补齐或验收，不计入应采数量和缺口。
- mootdx 不提供交易所级服务承诺。
- mootdx 分笔查询不等同于完整 Level-2 逐笔行情流。
- 系统必须展示数据覆盖率和缺口，不得将不完整分笔标记为完整。
- P95 不超过 3 秒是健康数据源下的系统目标，不是对第三方源的保证。
- 第一期不包含自动实盘下单能力变更。

## 3. 功能需求

### 3.1 证券与来源

- **FR-CNMD-001** 系统必须维护上交所、深交所全部在市及历史 A 股证券；
  从 Provider 获取的证券全集必须按 SSE/SZSE 筛选。
- **FR-CNMD-002** 每只证券必须保留标准代码、市场、交易所、名称、状态、
  可获取的上市状态及 mootdx 代码映射。
- **FR-CNMD-003** 每条数据必须保存 Provider、来源服务器、请求参数、
  源时间、采集时间、标准化版本和内容哈希。
- **FR-CNMD-004** 原始供应商数据与标准化数据必须分开保存。

### 3.2 实时行情

- **FR-CNMD-005** 系统必须循环采集全市场实时行情及 mootdx 返回的全部盘口字段。
- **FR-CNMD-006** 自选股和策略池最新行情从源时间到标准化数据可用的
  P95 延迟不得超过 3 秒。
- **FR-CNMD-007** 最新行情必须通过 WebSocket 增量推送，客户端断线后可用
  REST 快照恢复。
- **FR-CNMD-008** 完全相同的连续快照允许逻辑去重，但原始采集批次及哈希
  必须保留，以证明采集发生过。

### 3.3 K 线、分时与分笔

- **FR-CNMD-009** 系统必须保存 mootdx 支持的全部 K 线周期及复权类型。
- **FR-CNMD-010** 系统必须保存实时分时、历史分时、当前分笔和历史分笔。
- **FR-CNMD-011** 分笔采集必须保存分页游标、覆盖区间和缺口状态。
- **FR-CNMD-012** K 线和分笔必须支持按证券、时间范围、周期和复权类型查询。

### 3.4 基础资料与财务数据

- **FR-CNMD-013** 系统必须保存证券列表、指数、板块及板块成分的历史版本。
- **FR-CNMD-014** 系统必须保存除权除息事件及复权因子。
- **FR-CNMD-015** 系统必须保存 F10 目录、F10 原文及内容哈希。
- **FR-CNMD-016** 系统必须保存 Affair 原始财务文件、文件哈希和解析结果。
- **FR-CNMD-017** 文件内容变化时必须创建新版本，不得覆盖历史版本。

### 3.5 数据质量与恢复

- **FR-CNMD-018** 系统必须检测重复、乱序、缺失、陈旧、异常价格、
  盘口倒挂和累计成交量回退。
- **FR-CNMD-019** 系统必须在 MOOTDX 数据内部核对交易日、证券状态、收盘价、
  成交量、成交额和复权字段的一致性。
- **FR-CNMD-020** 冲突数据必须保留双方原值、差异和裁决结果。
- **FR-CNMD-021** 数据超过新鲜度阈值或存在严重冲突时，策略不得使用该数据
  生成开仓信号。
- **FR-CNMD-022** 采集服务重启后必须从持久化游标继续，并支持指定证券、
  数据类型和时间范围的人工补采。

### 3.6 前端

- **FR-CNMD-023** “数据”模块必须提供全市场、个股分析、数据目录和数据运维
  四个页面。
- **FR-CNMD-024** 全市场页面必须支持搜索、筛选、排序、虚拟滚动、自选股
  和策略池操作。
- **FR-CNMD-025** 个股页面必须提供行情摘要、分时、K 线、五档盘口、分笔、
  财务、除权除息、F10 和数据来源视图。
- **FR-CNMD-026** 数据运维页面必须展示采集任务、来源服务器、延迟、覆盖率、
  缺口、补采任务和存储容量。
- **FR-CNMD-027** 所有行情视图必须显示源时间、新鲜度和质量状态，不能仅以
  颜色表达异常。
- **FR-CNMD-028** 前端必须提供加载、空数据、断流、陈旧、部分覆盖、错误和
  重连状态。

## 4. 非功能需求

- **NFR-CNMD-001** 健康数据源下，自选股和策略池行情新鲜度 P95 不超过 3 秒。
- **NFR-CNMD-002** 最新行情 REST 查询 P95 不超过 300 ms。
- **NFR-CNMD-003** 历史 K 线常规查询 P95 不超过 500 ms。
- **NFR-CNMD-004** 已写入 Kafka 的行情事件不得因消费者重启而永久丢失。
- **NFR-CNMD-005** 原始文件必须支持按 Provider、数据类型、交易日和批次回放。
- **NFR-CNMD-006** 重复消费不得产生重复标准记录。
- **NFR-CNMD-007** Redis 丢失后必须能够从持久化数据重建最新行情。
- **NFR-CNMD-008** 前端不得一次渲染全部证券 DOM 行，必须使用虚拟列表。
- **NFR-CNMD-009** 页面在 1280 px 桌面宽度和 390 px 移动宽度下不得出现
  文本遮挡或不可达操作。
- **NFR-CNMD-010** Token、连接配置和本地文件路径不得出现在浏览器日志、
  服务日志或导出文件中。

## 5. 数据保留

- 原始行情批次、原始财务文件和 F10 原文永久保留。
- 标准化行情、K 线、分笔和质量记录永久保留。
- ClickHouse 热数据默认保留 90 天，之后迁移到低成本本地磁盘或 MinIO，
  不执行数据删除。
- Redis 只保存最新快照和短期状态，不承担永久保存责任。
- Kafka 默认保留 7 天，最终事实以 ClickHouse、MySQL 和 MinIO 为准。

## 6. 验收原则

1. 能从空库完成证券主数据和历史数据初始化。
2. 交易时段可持续采集全市场快照，并证明自选股和策略池 P95 新鲜度。
3. mootdx 各数据类型均有原始落盘、标准化表和可查询入口。
4. 服务重启、网络断开和重复消息后数据仍可恢复且不重复。
5. 前端能够完成全市场浏览、个股分析、质量检查和人工补采闭环。
6. 分笔不完整时必须明确展示覆盖缺口。
7. 应采数量、覆盖率和缺口仅按沪深证券计算；范围外交易所未采集不得导致
   `partial` 或 `degraded`。沪深数据质量和新鲜度要求仍按原标准执行。
