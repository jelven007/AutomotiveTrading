# 量化交易 SaaS 需求规格说明书

> 文档编号：QT-SRS-001
>
> 版本：1.3-draft
>
> 基线来源：`docs/plans/2026-09-18-quant-trading-saas-spec.md`

币安专项需求以
[`QT-REQ-BIN-NT-001`](binance-nautilustrader-requirements.md)
为准。

## 1. 引言

### 1.1 目的

本文定义量化交易 SaaS 第一期可验证的软件需求。需求使用唯一编号，
作为设计、开发、测试、验收和变更管理的依据。

### 1.2 产品范围

系统提供首页、资讯、策略、交易、数据五个一级模块，支持 A 股、港股、
美股和币安数字资产市场，面向多租户用户提供 Python 策略、大模型决策、
回测、模拟交易及受控实盘交易能力。

A 股数据范围于 2026-09-20 确认为上交所（SSE）和深交所（SZSE），
北交所不属于采集、补齐、查询展示及验收范围。

### 1.3 术语

| 术语 | 定义 |
| --- | --- |
| 租户 | 独立订阅、数据和权限边界 |
| 标的池 | 策略分析的一组标准证券 |
| 模型配置 | 租户管理员创建的模型供应商连接与推理参数 |
| 候选决策 | 模型返回但尚未通过组合协调和风控的结果 |
| 自动交易 | 策略决策通过授权和风控后自动提交 |
| Connector | 隔离运行的券商、交易所或模拟盘接入服务 |
| 全仓杠杆 | 多个资产共享同一杠杆账户抵押品和风险水平 |
| 逐仓杠杆 | 每个交易对独立计算资产、负债和强平风险 |
| U 本位永续 | 以 USDT/USDC 等稳定币计价和结算的永续合约 |

## 2. 用户与权限需求

- **FR-IAM-001** 系统必须支持用户注册、登录、退出和会话撤销。
- **FR-IAM-002** 系统必须支持一个用户加入多个租户。
- **FR-IAM-003** 每个请求必须绑定唯一活动租户。
- **FR-IAM-004** 系统必须提供平台管理员、租户管理员、研究员、交易员、
  审计员五类角色。
- **FR-IAM-005** 系统必须对页面、API 和资源所有权同时鉴权。
- **FR-IAM-006** 新增实盘账户、开启自动交易、修改关键风控和解除急停
  必须进行 MFA。
- **FR-IAM-007** 普通成员不得查看、导出或修改模型与券商密钥。

## 3. 首页需求

- **FR-HOME-001** 展示三地市场指数、交易状态和行情时间。
- **FR-HOME-002** 展示用户自选股行情。
- **FR-HOME-003** 分开展示模拟与实盘资产、盈亏和币种。
- **FR-HOME-004** 展示运行中、暂停和异常策略。
- **FR-HOME-005** 展示回测进度和待确认交易信号。
- **FR-HOME-006** 展示数据延迟、券商断连和风险告警。
- **FR-HOME-007** 支持跳转创建策略、回测、下单和数据查询。

## 4. 资讯需求

- **FR-NEWS-001** 支持新闻、公告、研报、宏观和财报事件。
- **FR-NEWS-002** 支持按市场、行业、标的、来源、时间和类型筛选。
- **FR-NEWS-003** 支持关键词、自选股和标的池订阅。
- **FR-NEWS-004** 资讯必须记录发布时间、采集时间和来源。
- **FR-NEWS-005** 系统必须识别重复内容并保留来源关系。
- **FR-NEWS-006** 策略可读取指定时点之前的资讯快照，禁止未来数据泄漏。

## 5. 数据需求

- **FR-DATA-001** 使用统一模型描述 A 股、港股、美股证券。
- **FR-DATA-002** 维护平台证券与各供应商、券商代码的显式映射。
- **FR-DATA-003** 提供证券、交易日历、K 线、快照、公司行动、财务、
  行业和因子接口。
- **FR-DATA-004** 数据必须保留来源时间、采集时间、版本、时区和币种。
- **FR-DATA-005** 页面必须展示字段说明、频率、来源、新鲜度和样例。
- **FR-DATA-006** Mock Provider 必须使用生产 Schema，并模拟延迟、缺失、
  限流和故障。

A 股生产数据子域由
[`QT-SRS-CNMD-001`](a-share-market-data-requirements.md) 细化。该专项基线
要求使用 MOOTDX 采集沪深范围内可提供的全部数据并在本地永久保存，
同时提供全市场、个股分析、数据目录和数据运维前端页面。
这里的“全市场”、证券全集和覆盖统计均仅指 SSE/SZSE。
当本节与专项基线存在粒度差异时，以专项基线为准。

## 6. 策略需求

- **FR-STR-001** 用户可创建、复制、编辑、校验、发布、暂停和归档策略。
- **FR-STR-002** 策略运行必须绑定不可变版本。
- **FR-STR-003** 策略支持 Python 源码、模板、日志和静态检查。
- **FR-STR-004** 标的池支持手工、CSV、自选股、指数和规则筛选。
- **FR-STR-005** 自定义参数使用 JSON Schema，支持范围、枚举、默认值和
  环境覆盖。
- **FR-STR-006** 策略支持定时和行情事件双触发。
- **FR-STR-007** 策略支持单股冷却、调用上限、并发和费用预算。
- **FR-STR-008** 自动实盘策略必须依次完成校验、回测、模拟和审批。

## 7. 模型配置需求

- **FR-MDL-001** 系统必须提供“租户设置 > 模型服务”配置中心。
- **FR-MDL-002** 仅租户管理员可新增、修改、停用或删除模型配置。
- **FR-MDL-003** 普通成员只能选择已启用的模型配置。
- **FR-MDL-004** 支持 OpenAI、Anthropic、DeepSeek、OpenAI Compatible、
  Ollama 和 vLLM 类型。
- **FR-MDL-005** 配置包含名称、Base URL、Model ID、API Key、超时、
  重试、并发、采样参数、Token 限额和费用预算。
- **FR-MDL-006** 支持设置默认模型、备用模型及允许使用的执行环境。
- **FR-MDL-007** API Key 写入后不可回显，只允许替换或吊销。
- **FR-MDL-008** 云端模型和 OpenAI Compatible 支持连接测试。
- **FR-MDL-009** Ollama/vLLM 第一期仅保存和校验配置，标记“待开放”，
  不允许策略选择，不发起网络连接。
- **FR-MDL-010** 删除被策略引用的配置前必须停用或迁移相关策略。
- **FR-MDL-011** 所有模型配置变更和连接测试必须审计。

## 8. AI 决策需求

- **FR-AI-001** 标的池内每只股票必须建立独立模型任务。
- **FR-AI-002** 相同租户、策略版本、标的、触发类型和市场时间只能生成
  一条有效决策。
- **FR-AI-003** 输入必须包含行情、特征、资讯、账户、持仓、风险和时间。
- **FR-AI-004** 关键数据缺失、过期、停牌或休市时返回观望，不调用模型。
- **FR-AI-005** 模型输出必须符合固定 JSON Schema。
- **FR-AI-006** 输出支持买入、卖出、观望、置信度、目标仓位、订单类型、
  限价、有效期、理由和风险标记。
- **FR-AI-007** 非法、超时、低置信度、矛盾或过期结果必须降级为观望。
- **FR-AI-008** 模型不得选择账户、密钥、券商或跳过风控。
- **FR-AI-009** 单股决策必须通过组合协调器解决资金与敞口冲突。
- **FR-AI-010** 保存模型、版本、提示词、输入快照、原始响应和解析结果。

## 9. 回测需求

- **FR-BT-001** 回测任务必须异步执行。
- **FR-BT-002** 回测固定策略、参数、标的池、数据版本、费用和随机种子。
- **FR-BT-003** Python 代码必须在限制 CPU、内存、磁盘、进程和时间的
  非特权容器中运行。
- **FR-BT-004** Runner 默认禁止外网访问。
- **FR-BT-005** 输出收益、风险、回撤、交易、持仓、费用和模型决策报告。
- **FR-BT-006** 相同输入和运行镜像必须可复现。

## 10. 交易需求

- **FR-TRD-001** 交易模块分为模拟交易和实盘交易。
- **FR-TRD-002** 当前环境、账户、券商、市场时间和连接状态必须持续可见。
- **FR-TRD-003** 支持平台模拟撮合。
- **FR-TRD-004** 支持同花顺模拟盘 Adapter。
- **FR-TRD-005** 支持富途 OpenD 实盘 Adapter。
- **FR-TRD-006** 支持财信证券经正式确认的 QMT/PTrade 等实盘 Adapter。
- **FR-TRD-007** 支持人工下单和策略信号人工确认。
- **FR-TRD-008** 支持按策略开启自动实盘，且默认关闭。
- **FR-TRD-009** 支持账户、资金、持仓、委托、撤单、成交和盈亏查询。
- **FR-TRD-010** 所有写订单必须具有幂等键。
- **FR-TRD-011** 券商超时后订单进入 `unknown`，禁止自动重复提交。
- **FR-TRD-012** 每笔实盘订单必须关联人工操作或已审批策略决策。
- **FR-TRD-013** 交易页面必须固定提供“沪深”“港美”“币安”三个二级
  入口，并在每个页面右上角提供“添加帐号”操作。
- **FR-TRD-014** 沪深一期支持绑定同花顺和财信证券；港美一期支持绑定
  富途和长桥；币安一期支持绑定币安生产账户。
- **FR-TRD-015** 币安采用单帐号分阶段方案：阶段一查询权限、现货余额、
  U 本位余额和持仓，阶段二增加人工交易。
- **FR-TRD-016** 币安账户添加必须执行权限和产品可用性测试，并要求用户确认
  固定出口 IP 白名单；每个用户只允许一个帐号，重新绑定覆盖旧帐号。
- **FR-TRD-017** 币安 API 凭据必须使用 ECS 只读主密钥文件和 AES-256-GCM
  加密入库，首版只支持 HMAC；凭据、密文和 nonce 不得回显或进入日志。
- **FR-TRD-018** 币安阶段一必须按需查询现货余额，不持久化资产历史。
- **FR-TRD-019** 币安阶段一必须查询 U 本位余额和非零持仓；Spot 与 USD-M
  单侧失败时另一侧继续可用。
- **FR-TRD-020** 币安帐号绑定和只读查询不要求 MFA；阶段二交易写操作必须通过
  短时 MFA 交易会话。
- **FR-TRD-021** 币安阶段二支持现货和 U 本位市价/限价单、单笔撤单，以及
  U 本位杠杆和 `cross|isolated` 保证金模式。
- **FR-TRD-022** 币安账户状态和执行统一通过精确锁版的 NautilusTrader 公共
  API；仅 API Key 权限检查允许使用受限的签名 REST 探测。

## 11. 风控与对账需求

- **FR-RSK-001** 下单前校验权限、时段、标的、资金、持仓、价格、频率、
  集中度、敞口、亏损、置信度和数据新鲜度。
- **FR-RSK-002** 风控不可用时必须拒绝交易。
- **FR-RSK-003** 支持租户、账户、策略、券商和平台五级急停。
- **FR-RSK-004** 保护模式只允许撤单和风险降低操作。
- **FR-RSK-005** 币安现货杠杆不属于当前范围，系统必须拒绝借款、还款、划转
  和现货杠杆订单请求。
- **FR-RSK-006** 币安 U 本位写入必须校验 instrument 允许的杠杆范围、
  `cross|isolated` 保证金模式、交易权限和账户状态新鲜度。
- **FR-RSK-007** 币安当前不建设独立风险配置和自动策略交易；高级仓位及强平
  风险控制在后续需求中单独评审。
- **FR-REC-001** 按事件和定时任务对账订单、成交、持仓、资金和费用。
- **FR-REC-002** 重大差异必须限制账户、创建事件并通知授权人员。
- **FR-REC-003** 解除限制必须填写结论并保留审批审计。

## 12. SaaS 与管理需求

- **FR-SAA-001** 支持套餐、权益、配额、用量和账单记录。
- **FR-SAA-002** 配额覆盖成员、策略、回测、数据、模型和券商连接。
- **FR-SAA-003** 昂贵任务必须在入队前校验配额。
- **FR-SAA-004** 用量采用追加记录并支持供应商账单对账。

## 13. 非功能需求

### 13.1 安全

- **NFR-SEC-001** 密钥不得明文保存；模型与其他券商使用 KMS，币安使用
  ECS 本地主密钥和 AES-256-GCM。浏览器与策略容器不可读取持久化密钥。
- **NFR-SEC-002** 日志必须脱敏账号、Token 和密钥。
- **NFR-SEC-003** 关键配置、模型决策、人工确认和订单状态追加审计。
- **NFR-SEC-004** 外部资讯视为不可信输入，必须防提示词注入。
- **NFR-SEC-005** 必须通过租户越权和恶意代码测试。

### 13.2 可靠性

- **NFR-REL-001** 查询接口月可用性目标 99.9%。
- **NFR-REL-002** 交易时段写链路月可用性目标 99.95%。
- **NFR-REL-003** 已确认订单事件不得丢失。
- **NFR-REL-004** 交易数据 RPO 不超过 5 分钟。
- **NFR-REL-005** 核心服务 RTO 不超过 30 分钟。

### 13.3 性能

- **NFR-PERF-001** 常规查询 P95 响应时间不超过 500 ms，不含外部供应商。
- **NFR-PERF-002** 下单请求完成平台风控的 P95 不超过 300 ms。
- **NFR-PERF-003** 行情事件触发入队 P95 不超过 1 秒。
- **NFR-PERF-004** WebSocket 连接和租户并发能力按压测基线验收。

### 13.4 可观测性

- **NFR-OBS-001** 所有跨服务请求携带 Trace ID 和 Tenant ID。
- **NFR-OBS-002** 监控行情延迟、模型成本、风控、订单、对账和队列。
- **NFR-OBS-003** 严重故障必须触发分级告警。

### 13.5 可维护性

- **NFR-MNT-001** 外部 Provider 和 Broker 必须通过版本化 Adapter 接入。
- **NFR-MNT-002** 外部 API、内部 gRPC 和事件 Schema 必须版本化。
- **NFR-MNT-003** 服务不得直接访问其他服务数据库。

## 14. 约束与依赖

- 生产部署在火山引擎中国区。
- 外部券商与同花顺能力以正式合同和技术文档为准。
- 币安生产接入必须满足账户主体所在司法辖区、币安服务条款及当地法律要求；
  不满足时禁止绑定或交易。
- 当前币安方案面向个人单用户 ECS，不承诺多个帐号并行在线交易。
- 生产行情与资讯上线前必须取得合法采购和再分发权。
- Ollama/vLLM 一期不产生实际调用。
- 自动实盘上线前必须完成法律、安全和小额灰度验收。

## 15. 验收原则

每项 `FR-*` 必须至少对应一个设计组件和一个测试用例；
每项 `NFR-*` 必须有可执行验证方法。未满足外部依赖的能力允许使用
经批准的 Stub 完成内部验收，但不得标记为真实接入完成。
